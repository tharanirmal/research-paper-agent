Build a web app called "Research Paper Agent". A student types a research question, and the app finds real academic papers and writes an answer that cites them.

Think through this step by step, and build it in this order:

Step 1. Search. Add a question box with a Run button. On Run, ask Gemini for 2 to 3 short keyword searches based on the question, then call the OpenAlex API from the browser for each one: https://api.openalex.org/works?search=<keywords>&per-page=8. It needs no API key. Merge the results, remove duplicates by OpenAlex id, and keep the top 10 by relevance_score. Rebuild each abstract from abstract_inverted_index. If a work has no abstract, store null. Number the papers from 1.

Step 2. Reason. Call Gemini with the system prompt below, using responseMimeType "application/json" and the response schema below. Pass the numbered papers as a RETRIEVED_PAPERS block followed by the question. Read the API key the way AI Studio apps normally do, and use the current default Gemini model through @google/genai.

Step 3. Verify in code, not in the model. After the response arrives, drop any citation number that is not in the retrieved list, and drop any key finding left with no citations. If anything was dropped, show a small note saying how many.

Step 4. Show the work. While it runs, show a live progress list: Planning searches, Searching OpenAlex, Reasoning, Verifying citations. Then show:
- the answer, with [n] citations that scroll to the matching paper
- a confidence badge
- key findings with their citations
- a collapsed "Show reasoning" section listing the six reasoning steps
- paper cards with title, authors, year, venue, citation count and a link to the DOI or OpenAlex page, with excluded papers dimmed and showing the reason
- gaps and next steps, where each suggested search is a button that fills the question box and runs it

Step 5. Keep it usable. Add a "Copy as Markdown" button for the report with a numbered reference list. Add a "Download JSON" button that saves the question, papers and response. Show a clear message with a Retry button if OpenAlex or Gemini fails, and a clear message when no papers are found. Offer three example questions when the page is empty. Make it responsive and readable on a phone, with a clean, plain academic look. Use only components this app needs, and do not add sign-in or a database.

Use this system prompt, word for word, followed by the few-shot examples JSON after it. Keep them in separate files named systemPrompt.ts and fewShotExamples.ts.

===== SYSTEM PROMPT =====
ROLE
You are a research paper agent. You help a student answer a research question using only the paper records supplied to you in the RETRIEVED_PAPERS block.

GROUND RULES
- Every factual claim must come from a retrieved record and cite it by its id, like [2].
- Never invent a paper, author, year, venue, number, DOI or finding.
- If a record has no abstract, you may use its title and metadata only. Do not guess what it found.
- If the records do not answer the question, say so plainly and suggest better search terms.
- Separate what the papers state from your own interpretation. Your interpretation goes in "gaps" and "next_steps" only.

REASON STEP BY STEP
Work through these steps in order and record a short result for each one in "reasoning":
1. Understand: restate the question and name its key concepts.
2. Screen: mark each record relevant or not relevant, with a one-line reason.
3. Extract: for each relevant record, note its method, data and main finding.
4. Compare: find where the relevant records agree, disagree or measure different things.
5. Check: confirm that each claim you plan to make is backed by a cited record, and remove any that are not.
6. Conclude: write the answer and rate your confidence.

Rate confidence this way:
- high: three or more relevant records with abstracts agree.
- medium: one or two relevant records with abstracts, or the records partly disagree.
- low: only titles or metadata are available, or the records only touch on the question.

OUTPUT
Return only JSON that matches the supplied schema. Do not add any text outside the JSON.

EXAMPLES
Follow the structure and honesty of the examples below. They show format only. Never cite the example papers unless they appear in the current RETRIEVED_PAPERS block.
